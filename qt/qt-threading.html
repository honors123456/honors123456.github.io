Qt 多线程与异步任务

对比 QThread、QRunnable 与 QtConcurrent，帮助你正确选择并发模型并保持 GUI 响应性。

01

QThread 模型

QThread 适用于需要独立事件循环、精细控制线程生命周期或长期后台任务的场景。通过将 QObject 移动到线程，可以在子线程中运行槽函数，并通过信号在主线程中更新 UI。

class Worker : public QObject {
  Q_OBJECT
public slots:
  void doWork() {
    // 运行耗时任务
  }
};

QThread* thread = new QThread;
Worker* worker = new Worker;
worker->moveToThread(thread);
connect(thread, &QThread::started, worker, &Worker::doWork);
connect(worker, &Worker::finished, thread, &QThread::quit);
connect(thread, &QThread::finished, worker, &QObject::deleteLater);
thread->start();
02

QRunnable 与线程池

QRunnable 更适合短生命周期任务，它与 QThreadPool 结合使用可以减少线程创建开销。提交任务时可设置自动删除模式，让 Qt 线程池负责对象回收。

class Task : public QRunnable {
  void run() override {
    // 执行任务
  }
};

Task* task = new Task;
task->setAutoDelete(true);
QThreadPool::globalInstance()->start(task);
03

QtConcurrent 简化并行

QtConcurrent 提供高层 API 来执行后台任务、并行 map/reduce 或数据流处理。它适合不需要手动管理线程的场景，并可通过 QFutureWatcher 在完成后通知 UI。

auto future = QtConcurrent::run([]() {
  // 后台工作
});
QFutureWatcher watcher;
connect(&watcher, &QFutureWatcher::finished, []() {
  // 更新 UI
});
watcher.setFuture(future);
04

线程安全与 UI 更新

Qt GUI 只能在主线程中访问，任何从后台线程返回的结果都应通过信号槽或 QMetaObject::invokeMethod 传递。避免共享可变数据，必要时使用 QMutex 或 QReadWriteLock 保护临界区。
