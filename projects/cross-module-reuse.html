跨模块复用策略

总结 C++ 核心库与 UI 模块之间的接口设计与复用实践。

01

接口驱动设计

将核心算法和数据结构暴露为干净接口，避免 UI 层直接依赖实现细节。良好的接口定义可以降低模块间耦合，并使单元测试变得可行。

02

模块边界

区分引擎模块、展示模块与工具模块，提高替换与扩展能力。比如把图像处理、渲染和配置管理分别作为独立库维护。

03

共享库

把通用工具、数据结构和算法提取成静态或动态库，多个项目可直接复用。通过 CMake 管理依赖关系，让上层应用仅链接所需模块。

add_library(core STATIC src/core.cpp)
add_library(ui STATIC src/ui.cpp)
target_link_libraries(ui PRIVATE core)
04

数据契约

为模块间传递的数据定义明确结构，如 JSON、protobuf 或自定义 DTO。保持跨模块数据契约稳定，避免频繁修改接口。
